# 开发者须知

## 本地开发环境

本项目必须通过根目录的 `tModLoader.local.props` 文件定位本机的 Steam tModLoader 安装目录。它是本机环境配置，已被 Git 忽略，不应提交。
通过初始化脚本可以自动生成 `tModLoader.local.props` 文件。
初始化脚本会优先从 Steam 默认目录和 Steam 库配置中自动定位 tModLoader；找不到时会生成一个待填写的模板。

在克隆项目后需要运行一次初始化脚本（需要 Node.js 18+）：

```sh
node scripts/setup-tmodloader.js
```

使用 Yarn 也可以：

```sh
yarn setup:tmodloader
```

若 tModLoader 安装在非标准位置，可显式传入安装目录：

```sh
node scripts/setup-tmodloader.js --tmodloader-path "D:/SteamLibrary/steamapps/common/tModLoader"
```

```sh
yarn setup:tmodloader --tmodloader-path "D:/SteamLibrary/steamapps/common/tModLoader"
```

脚本会生成 `tModLoader.local.props` 和 `.vscode/launch.json`，并在本地服务器配置不存在时从示例创建 `serverconfig.local.txt`。
在 macOS 与 Windows 间切换或需要重新定位安装目录时，运行 `node scripts/setup-tmodloader.js --force`；也可以先修改本地配置中的 `TModLoaderPath`，再运行初始化脚本更新调试配置。不需要改动 `.csproj` 或 VS Code 任务。

```xml
<TModLoaderPath>/你的/tModLoader/安装目录</TModLoaderPath>
```

常见安装路径：

- macOS：`/Users/你的用户名/Library/Application Support/Steam/steamapps/common/tModLoader`
- Windows：`C:/Program Files (x86)/Steam/steamapps/common/tModLoader`

开发机需已安装 Steam 版 tModLoader、.NET 8 SDK 与 Node.js 18+，VS Code 需要 C# 调试扩展。打开解决方案后，使用 `Cmd+Shift+B`（Windows 为 `Ctrl+Shift+B`）构建。

## 多人模式调试

支持 Windows 和 macOS。以下命令均在项目根目录执行。

1. 运行 `npm run setup:tmodloader`，按当前系统生成本机的 tModLoader 路径和 VS Code 调试配置。若未找到 Steam 安装，可运行 `npm run setup:tmodloader -- --tmodloader-path "你的 tModLoader 安装目录" --force`。
2. 编辑 `serverconfig.local.txt`，将 `world` 设置为已有 `.wld` 文件的绝对路径。路径含空格也不加引号。
3. 运行 `yarn start:client`，由 VS Code 编译模组并启动客户端断点调试。
4. 在另一个终端运行 `yarn start:server`，以非调试方式启动服务器，直接加载配置中的世界，无需选择世界、人数、端口或密码。
5. 客户端通过 IP `127.0.0.1` 加入，端口使用本地配置中的 `port`。

也可以使用 `yarn start`，通过菜单选择客户端调试或服务器非调试运行。Windows 与 macOS 使用相同命令：

```sh
yarn start
yarn start client             # 等同于 yarn start:client
yarn start server             # 等同于 yarn start:server
```

客户端命令通过项目内的 `ScourgeMod Yarn Start` 本地 VS Code 扩展调用 C# 调试器，可使用断点、暂停、单步和变量检查。首次运行会自动将此扩展安装到本机；若 VS Code 提示是否允许扩展打开链接，选择允许。扩展源码位于 `scripts/vscode-debug-extension`，无需发布到扩展市场。需要已安装 VS Code 和 C# 扩展；VS Code 不在常见安装位置时，请先将 `code` 命令加入 PATH。

服务器命令使用已有的模组包，不执行构建，也不附加调试器。修改代码后，先停止服务器和加载模组的客户端，再重新运行 `yarn start:client` 构建，最后运行 `yarn start:server`。这样可以避免正在运行的进程占用模组包。

仅查看启动配置、不打开游戏或安装扩展：

```sh
yarn start:client --dry-run
yarn start:server --dry-run
```

原有 F5 入口仍可使用：`Debug tModLoader Client` 直接调试客户端，`Debug tModLoader` 弹出客户端 / 服务器选择。macOS 上服务器使用上述 `yarn start:server` 普通运行方式。

服务器的本地配置示例见 [serverconfig.example.txt](../serverconfig.example.txt)：

- `world`：世界文件的绝对路径。
- `maxplayers`：人数上限，默认 `4`。
- `port`：端口，默认 `7777`。
- `password`：密码，留空表示无密码。
- `upnp`：自动端口映射，本机调试默认关闭。

Windows 的世界路径可写成 `C:\Users\你的用户名\Documents\My Games\Terraria\tModLoader\Worlds\世界名.wld`；
macOS 可写成 `/Users/你的用户名/Library/Application Support/Terraria/tModLoader/Worlds/世界名.wld`。
两种系统都直接填写原始路径，不需要将反斜杠写成 `\\`。

`Properties/launchSettings.json` 中的 `TerrariaServer` 也读取同一份本地配置。
服务器以 `-nosteam` 启动，客户端通过 IP 连接。停止服务器时在终端输入 `exit` 保存世界并退出。

`tModLoader.local.props`、`serverconfig.local.txt` 和 `.vscode/launch.json` 已被 Git 忽略；本地服务器配置也已从 `.tmod` 打包中排除。
配置生成脚本保留已有的 `serverconfig.local.txt`，再次运行不会覆盖自定义值。

## 多开客户端

Windows 和 macOS 使用相同命令。在项目根目录运行：

```sh
yarn client
```

每执行一次，新增一个独立客户端；也可以一次打开多个：

```sh
yarn client --count 2
```

脚本直接读取 `tModLoader.local.props` 中的 `TModLoaderPath`，与 F5 共用安装路径、运行时和原生库配置，无需再填写路径。
优先使用游戏自带的 .NET 运行时，并为 macOS 和 Windows 设置相应的原生库路径。客户端在后台运行，命令完成后可以继续使用终端。

仅检查启动配置、不打开游戏：

```sh
yarn client --dry-run
```

客户端以 `-nosteam` 启动。各客户端选择不同角色，通过 IP `127.0.0.1` 和本地服务器配置中的端口加入同一服务器。
该命令不会构建模组或附加调试器；需要断点的客户端使用 `yarn start:client` 或 F5 启动。
